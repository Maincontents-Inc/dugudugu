# 두구두구 🥁

팀 순서를 **공정하게** 정하는 웹 미니게임 플랫폼입니다.
행사·캠프 현장에서 프로젝터에 띄워놓고 진행자가 클릭만 하면 됩니다.
발표 순서, 상품 추첨, 순위 정하기 — **용도를 고르면 화면 표현이 통째로 바뀝니다.**

- 빌드 도구 없는 정적 사이트 — GitHub Pages에 그대로 올라갑니다
- 파일을 내려받아 `index.html` 을 더블클릭해도 그대로 동작합니다 (인터넷 불필요)
- **PC·태블릿·폰 모두 대응** — 프로젝터에 띄워도, 폰으로 열어도 동작합니다
- 모든 게임이 **2~20팀** 지원
- 행사 제목·부제·글꼴을 넣으면 게임 화면과 결과, 저장 이미지에 함께 표시됩니다

---

## 게임

| 게임 | 설명 |
|---|---|
| 🪜 **사다리타기** | 팀마다 구슬이 사다리를 타고 내려가 순서를 정합니다. 한 팀씩 개별 진행 또는 전체 동시 진행. |
| 🎱 **마블 레이스** | 팀마다 구슬이 코스를 굴러 내려가고, 결승선을 통과한 순서가 그대로 결과가 됩니다. |

---

## 쓰는 법

1. **팀 이름**을 넣습니다. `여러 줄 붙여넣기` 로 엑셀·메모장에서 한 번에 넣을 수 있고, 팀 수는 자동으로 맞춰집니다.
2. **행사 정보**(선택)에 제목·부제를 넣으면 게임 화면 왼쪽 위와 결과 화면, 저장 이미지에 표시됩니다. 비워두면 아무것도 나오지 않습니다.
   같은 칸의 **용도**를 고르면 결과 화면·도착 칸·저장 이미지의 표현이 한꺼번에 바뀝니다.
3. **게임**을 고르고 `시작하기`.
4. 결과가 나오면 `결과 이미지 저장` 으로 PNG를 받아 공지에 쓸 수 있습니다.

설정은 브라우저에 자동 저장되어 다음에 열어도 그대로 유지됩니다.

### 용도 프리셋

| 용도 | 결과 화면 제목 | 각 자리 | 저장 파일명 |
|---|---|---|---|
| 순서 정하기 (기본) | 순서 | `1번` | `순서_20260918.png` |
| 발표 순서 | 발표 순서 | `1번째 발표` | `발표순서_…` |
| 순위 | 순위 | `1등` | `순위_…` |
| 추첨 당첨 | 당첨 순서 | `1번째` | `추첨결과_…` |

문구는 `assets/core.js` 의 `PURPOSES` 한 곳에만 있습니다. 용도를 추가하려면 거기에 한 줄 넣으면
모든 게임에 자동으로 적용됩니다. 게임 쪽은 `host.slot(j)` 만 부르면 되므로 게임이 늘어나도
문구를 게임마다 고칠 일이 없습니다.

### 화면 크기

| 환경 | 동작 |
|---|---|
| 프로젝터·노트북 | 전체화면(`F`)으로 띄워 진행 |
| 태블릿 | 그대로 동작 |
| 폰 (세로) | 설정은 한 열로, 마블은 코스 위 순위 아래로 쌓입니다. 사다리는 칸 폭을 지키고 좌우로 밀어 보며, 구슬이 움직이면 화면이 따라갑니다 |
| 폰 (가로) | 세로 공간을 아끼려 부제·안내문을 숨깁니다 |

### 단축키

| 키 | 동작 |

| `R` | 사다리 다시 섞기 |

## 공정성

**두 게임 모두 모든 순서가 정확히 같은 확률로 나옵니다.** 원리는 다르지만 뿌리는 같습니다 —
`crypto.getRandomValues` 기반 Fisher-Yates 셔플입니다.

### 사다리타기 — 결과를 먼저 뽑고 사다리를 역산

가로줄을 무작위로 뿌리기만 하는 일반적인 사다리는 균등하지 않습니다. 사다리는 한 번에 옆으로
한 칸씩만 움직이는데 연결선 개수가 유한하니, 끝 줄은 끝에 머무를 확률이 높습니다.
(5팀·14행 실측: 1번 줄 → 1번 도착 **27.0%** vs 5번 도착 **12.7%**)

그래서 순서를 뒤집었습니다.

1. 결과 순열 π 를 균등하게 **먼저** 뽑습니다
2. 위·아래에 자유 랜덤 블록 A, B 를 깝니다
3. 가운데 보정 블록 C 를 **odd-even transposition network** 로 만들어 `B∘C∘A = π` 가 되게 맞춥니다 (`C = B⁻¹∘π∘A⁻¹`)

같은 결과를 만드는 사다리 모양이 무수히 많아서 **사다리는 매번 새로 그려집니다.**
상단 팀 순서는 입력한 그대로 고정되고, 화면의 사다리를 실제로 타고 내려간 결과가 곧 최종 결과입니다.
보정이나 눈속임은 없습니다.

### 마블 레이스 — 출발 슬롯을 균등하게 섞기

물리 시뮬레이션은 출발 위치에 따라 유불리가 생깁니다. 그래서 **출발 슬롯에 팀을 배정할 때**
균등 셔플을 씁니다.

- 구슬은 색과 번호만 다를 뿐 크기·질량·마찰이 완전히 동일합니다
- "어느 슬롯이 몇 등으로 들어오는가"는 물리가 정하고, "그 슬롯에 어느 팀이 있는가"는 균등 난수가 정합니다
- 최종 순위 = (슬롯 도착 순서) ∘ (균등 셔플) → 모든 n! 순서가 같은 확률

코스가 아무리 편향돼 있어도 결과는 완전 균등합니다. 공은 진짜로 굴러갑니다.

### 마블 코스 — 덕트처럼 꺾인 12종 구간

코스는 한 통으로 뻗은 수직 관이 아니라, **방을 위에서 아래로 이어 붙인 덕트**입니다.
다음 방의 가로 위치는 "이전 방의 출구가 새 방 안쪽에 들어오도록" 뽑기 때문에
벽은 반드시 맞물리고, 길은 좌우로 꺾이며 내려갑니다. 방 수는 팀 수에 따라 8~10개
(경주 20~30초 내외, 1배속 기준).

| 계열 | 방 | 하는 일 |
|---|---|---|
| 튀어오르는 것 | `pinball` `jump` `wheel` | 범퍼 6개 / 한쪽 점프대(위로 쏘아올림) / 회전 물레방아 |
| 벽 장치 | `saw` `wallbump` `narrow` | 톱니 벽 / 벽에 박힌 반구 / 좁아졌다 넓어지는 게이트 |
| 경로 | `split` `drop` `zigzag` `bowl` | 두 갈래 갈림길 / 자유낙하 / 엇갈린 경사면 / 4분원 미끄럼틀 |
| 움직이는 것 | `shuttle` `shutter` | 좌우 왕복 발판 / 위아래 셔터 |
| 관문 | `gate` | 깔때기 + 좌우로 미끄러지는 차단판 |
| 대기통 (항상 끝에서 두 번째) | `holdgate` | 통에 모였다가 바닥이 열리면 한꺼번에 쏟아진다 |
| 피날레 (항상 마지막) | `finale` | 반대로 도는 쌍둥이 날개 + 큰 범퍼. 결승선 직전 순위를 뒤집는다 |

방은 **실측 섞임도에 따라 가중치를 줘서** 뽑습니다. 잘 섞는 방(`jump` `zigzag` `drop`)이 더 자주 나옵니다.

코스는 **경주마다 새로 만들어집니다**(방 종류·순서·좌우 꺾임·회전 방향 전부 무작위).
게임 화면의 `코스 새로 만들기` 버튼으로 출발 전에 다시 뽑을 수도 있습니다.

화면은 선두 구슬을 따라가고, 오른쪽 위 **미니맵**에 코스 전체와 현재 보는 위치가 표시됩니다.

#### 끼임(구슬이 갇히는 것)을 막는 설계 규칙

물리 시뮬레이션에서 구슬이 끼는 원인은 거의 정해져 있어서, 방을 만들 때 아래를 규칙으로 못박았습니다.

1. **반발계수 1 초과 금지** — 튕길 때마다 에너지가 늘어나 발산합니다. 대신 "튕긴 뒤 속도를 정해진 값까지만 올리는" 고정 임펄스(BOOST)를 쓰고, 구슬마다 1.2초 쿨다운을 둡니다
2. **수평면 금지** — 평평한 발판·바닥은 구슬을 태우고 안 내려보냅니다. 모든 면과 방 바닥은 출구 쪽으로 기울입니다
3. **웅덩이 금지** — 호(arc)에 최저점이 들어가면 그 자리가 웅덩이가 됩니다. `bowl`은 4분원만 써서 한 방향으로만 흐르게 하고, 낮은 쪽 끝은 허공으로 둡니다
4. **뾰족한 꼭짓점 금지** — `split`의 쐐기 꼭짓점 자리에는 둥근 범퍼를 둡니다(뾰족하면 구슬이 그 위에서 균형을 잡습니다)
5. **겹침 금지** — 범퍼를 경사면 위에 겹쳐 놓으면 그 사이에 구슬 지름보다 좁은 틈이 생깁니다. 모든 틈은 구슬 지름의 2배 이상
6. **너무 완만한 경사 금지** — 방 폭 전체를 가로지르는 경사면은 기울기가 10도도 안 나와 구슬이 못 내려옵니다. 폭의 3/4만 쓰고 낙차를 키웁니다
7. **못밭 금지** — 파친코식 못밭을 빽빽하게 깔면 구슬이 그 안에서 오래 튀느라 못 빠져나옵니다(실측 평균 49초, 안전망 3단 963회). 피날레는 못밭 대신 회전 날개로 만듭니다
8. **점프대 방향** — 점프대는 반드시 **벽 쪽이 높고 안쪽이 낮게**. 반대로 놓으면 튕겨 올라간 구슬이 비스듬히 벽 모서리로 되돌아와 같은 점프대에 다시 떨어지는 고리가 생깁니다(실측 안전망 2단 27회)
9. **점프대 아래끝 높이** — 경사면의 낮은 끝은 바닥에서 최소 50px 위에서 시작. 바닥 안쪽에서 시작하면 기울어진 바닥과의 사이가 좁아져 끼입니다
10. **회전 날개 주변 여유** — 날개 회전 반경 + 물체 반지름 + 구슬 지름 이상 떨어뜨립니다. 가까우면 날개가 구슬을 정지 물체에 짓눌러 버립니다
11. **점프대 옆 범퍼에 킥 금지** — 쏘아올린 구슬을 범퍼가 다시 점프대로 차넣습니다

그 위에 **3단 안전망**이 깔려 있습니다(3초 이상 최고 도달점이 안 내려가면 흔들기 → 6초면 출구 쪽으로 밀기 → 10초면 출구 앞으로 옮기기).
안전망은 무작위로 흔드는 것이라 공정성에는 영향이 없지만(순위는 슬롯 셔플이 정함),
**설계가 제대로면 애초에 거의 발동하지 않아야 합니다.** 아래 검증 기록이 그 수치입니다.

### 순위가 실제로 섞이는가 — 방마다 측정한다

구슬이 물리적으로 굴러가는 레이스는 **앞선 구슬이 계속 앞서기 쉽습니다**(먼저 출구로 나가 다음
방에서도 앞서 출발하므로). 결과의 공정성과는 별개지만, 보는 재미가 떨어집니다.
그래서 방 하나하나가 실제로 순위를 얼마나 섞는지 계측해 설계에 반영했습니다.

- **섞임도** = 그 방을 지나는 동안 앞뒤가 뒤바뀐 순위쌍의 비율
- **선두유지율** = 코스 초반(3번째 방)에서 앞서던 구슬이 그대로 1등으로 들어오는 비율

측정으로 찾아낸 것들:

| 문제 | 원인 | 조치 |
|---|---|---|
| `wallbump` 섞임도 9% | 범퍼가 벽에만 붙어 있어 가운데로 떨어지는 구슬은 아무것도 안 맞고 통과 | 큰 범퍼를 중심선 너머까지 끌어와 좌우로 엇갈리게 |
| `saw` 섞임도 8% | 톱니가 벽에만 있고 가운데가 뚫려 있음 | 톱니를 깊게(38→54px) + 가운데 범퍼를 좌우 엇갈리게 |
| `split` 섞임도 9% | 두 갈래가 대칭이라 어느 쪽으로 가든 결과가 같음 | 한쪽만 방을 가로지르는 우회 경사면 — 통과 시간이 벌어짐 |
| 선두유지율 (초반 선두가 그대로 1등) | 20팀 22% · 12팀 22% · 5팀 46% (무작위 기준 5% · 8% · 20%) |
| 선두 교체 | 경주당 평균 2.1회(5팀) ~ 3.7회(12팀) |

#### 팀이 적을 때 — 장애물로는 안 되고, 관문이 필요하다

팀이 5개쯤이면 구슬끼리 부딪힐 일이 없어서 **어떤 장애물을 깔아도 선두가 유지됩니다.**
전부 `jump`, 전부 `zigzag`, 전부 `drop`, 전부 `pinball` 로 코스를 채워 각각 측정해 봤는데
선두유지율이 전부 40~43% 로 똑같았습니다. 장애물은 모든 구슬을 평균적으로 똑같이 지연시키므로
이미 벌어진 차이를 줄이지 못합니다.

차이를 **지우려면** 먼저 온 구슬이 손해를 보는 장치가 필요합니다. 그래서 결승선 직전에
**대기통(`holdgate`)** 을 고정으로 넣었습니다.

- 깔때기 아래 좁은 통이 있고, 통 바닥은 좌우로 미끄러지는 판입니다
- 판이 통을 덮고 있는 동안 구슬은 통에 갇혀 기다립니다 — **먼저 와도 문이 열릴 때까지 기다립니다**
- 판이 통을 완전히 벗어나면 안에 있던 구슬이 한꺼번에 쏟아지고, 바로 다음이 피날레입니다

설계 중 실패한 버전 두 가지를 기록해 둡니다.

| 시도 | 결과 |
|---|---|
| 판을 통보다 훨씬 넓게(판 260 / 통 200) | 마찰에 끌려다니는 구슬이 늘 판 위 덮인 쪽에 남아 **30초 넘게 안 떨어짐** |
| 물레방아식 회전 관문 | 구슬이 칸에 실리지 않고 통 바닥(=출구)으로 바로 떨어져 아무 효과 없음 |

최종형(판 200 / 통 140 / 이동폭 190)에서 **결승선 직전 1등이 뒤바뀌는 비율이 12~45%** 가 됐습니다.
결승선에서 구슬 대여섯 개가 한꺼번에 들어오는 장면이 자주 나옵니다.

결과: **선두유지율 20팀 22% · 12팀 22% · 5팀 46%**, 경주당 **선두 교체 2.1~3.7회**
(완전 무작위라면 선두유지율이 각각 5% · 8% · 20%).
5팀에서 선두가 절반쯤 유지되는 건 위에서 본 대로 물리적으로 불가피합니다.
**다만 어느 팀이 1등일 확률은 팀 수와 무관하게 정확히 1/n입니다**
(팀↔출발슬롯 배정이 매 경주 균등 셔플이므로).

### 직접 확인하기

브라우저에서 페이지를 열고 개발자도구 콘솔(F12)에 입력하면 직접 검증할 수 있습니다.

```js
__ladderAudit(5)        // 사다리 5팀 6만 회: 불일치 0, 출발×도착 분포
__ladderAudit(20, 5)    // 20팀
Core.auditShuffle(5)    // 셔플 균등성 (마블 공정성의 근거)
Core.auditShuffle(20)

__marbleStress(20, 40)  // 마블 20팀 40회 경주 — 미완주·끼임·소요시간
__marbleAnalyze(12, 60) // 방별 섞임도 · 선두유지율 · 선두 교체 횟수
__marbleDwell(8, 40)    // 방별 평균 체류시간 — 관문이 실제로 붙잡고 있는지 확인
```

`__marbleStress`는 마블 레이스 화면에 들어간 뒤에만 쓸 수 있고, 화면 없이 물리만 돌리므로 40회가 몇 초 만에 끝납니다.

`mismatch: 0` 은 "사다리를 실제로 타고 내려간 도착점"이 "뽑힌 결과"와 100% 일치한다는 뜻입니다.

## 사다리만 담은 단일 HTML

`사다리타기.html` — 사다리타기 하나만 들어 있는 **파일 한 개** 버전입니다.
`assets/` 없이 그것만 복사해 어디서든 더블클릭하면 실행됩니다. 메일로 보내거나
USB에 담아 현장 노트북에서 바로 쓸 때 편합니다. 기능·공정성은 동일합니다.

공용 파일(`assets/`)을 고친 뒤에는 아래 명령으로 다시 만들어야 반영됩니다.

```bash
node tools/build-single.mjs ladder "사다리타기" "사다리타기.html"
```

다른 게임도 같은 방식으로 뽑을 수 있습니다.

```bash
node tools/build-single.mjs marble "마블 레이스" "마블레이스.html"
```

게임이 하나만 등록된 빌드에서는 '게임 선택' 영역이 자동으로 숨겨집니다.

### 게임 추가하는 법

`assets/game-<이름>.js` 를 만들고 `index.html` 에 `<script>` 한 줄을 추가하면 끝입니다.

```js
Core.registerGame({
  id:'wheel', icon:'🎡', name:'룰렛', desc:'설명',
  optionsHtml(){ return '...'; },          // (선택) 설정 화면에 표시할 옵션 HTML
  bindOptions(root, o, save){ ... },       // (선택) 옵션 이벤트 연결
  start(h){ /* h.stage 에 그리고 h.finish(results) 로 끝낸다 */ },
  onResize(){}, onShow(){}, onKey(e){}, stop(){}
});
```

`h.finish(results)` 의 `results[j]` 는 **j+1번째 자리를 맡을 팀의 인덱스**입니다.
자리 이름은 `h.slot(j)` 로 가져오세요 (용도 프리셋이 반영된 문구가 나옵니다).
호스트가 제공하는 것: `h.teams`, `h.n`, `h.stage`, `h.settings`, `h.opts()`,
`h.tool(html)`(상단 버튼 추가), `h.slot(j)`·`h.purpose`(용도 프리셋 문구),
`h.setTip()`, `h.setCounter()`, `h.countdown()`,
`h.rnd/rndInt/shuffle`(암호학적 난수), `h.esc`, `h.lighten`, `h.toast`.

## 팀 표기 — 알파벳과 숫자를 나눠 씁니다

| 무엇 | 표기 | 어디에 |
|---|---|---|
| 팀 식별 | **알파벳** A·B·C… | 설정 화면 배지, 구슬 위 글자, 경주 중 순위판의 컬러 배지 |
| 순위·순서 | **숫자** 1·2·3… | 순위판 왼쪽 회색 숫자, 결과 화면 왼쪽 큰 숫자 |

구슬에 숫자를 쓰면 관객이 등수로 읽습니다. 그래서 팀은 알파벳, 순위는 숫자로 완전히 갈랐습니다.
결과 화면에서도 순위 숫자와 같은 뜻인 라벨(`1번`·`1등`·`1번째`)은 표시하지 않고,
정보가 더 있는 `발표 순서` 용도에서만 `1번째 발표`를 함께 보여줍니다.
